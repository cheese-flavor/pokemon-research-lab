# 작업 4: 검색어 추출·후보 선별·문서 색인

실행일: 2026-10-23. GMS `gpt-6.1-sol`로 프롬프트 1/2를 실제 실행하고, 질문별 문서를 별도 Chroma 컬렉션에 증분 색인했다. 근거 검색·LangGraph·답변 생성·화면은 다음 작업이다.

## 구현 범위와 출처

1. 정확한 한국어/영문명·전국도감 번호로 선택 항목을 결정한다. 고유명사 식별에 벡터 유사도만 사용하지 않는다. 별칭·오타의 폭넓은 자동 해석은 아직 지원하지 않는다.
2. 프롬프트 1이 검색어·문서 종류·요청 버전·미지원 범위·항목 변경 필요 여부를 JSON으로 반환한다. 선택 항목 이름은 코드가 항상 검색어에 추가한다. 허용 버전은 고정 원본 `versions.csv`에서 읽는다.
3. 원본 PokéAPI CSV 20개의 캐시 해시와 문서 출처 URL·리비전·항목 연결을 검사한다. 검색 대상은 고정 외부 출처의 로컬 카탈로그다. 선택 항목·진화 관계 및 검색어에 명시된 항목을 찾고 문서 종류·언어·버전·검색어 관련도로 최대 30개 후보를 구성한다.
4. 프롬프트 2는 제목·160자 이하 요약·언어·버전·생성 번역 여부를 보고 최대 8개 후보를 고른다. 모든 후보의 선택/제외 사유, 실제 doc_id 연결은 로컬 audit에 남긴다. 후보 밖 ID나 모순된 선택은 거절한다.
5. 선택 항목 자체의 도감·특성·진화 문서는 선별 결과와 합집합으로 포함한다. 모델이 제외하거나 짧은 설명이어도 누락시키지 않는다. 빈/손상 문서는 성공으로 처리하지 않는다.
6. 원문·출처·번역 provenance를 보존하고 청킹한 뒤 GMS `text-embedding-3-small` 1,536차원 벡터로 색인한다. 메타 컬렉션과 문서 컬렉션은 분리된다.

이 구현은 웹 전체 검색이나 실시간 PokéAPI 본문 검색이 아니다. 이미 외부에서 수집한 고정 원본을 재사용하며, 이번 실행의 외부 원본 요청 수는 0회다. 원본 파일 캐시가 없을 때는 기존 bulk 수집기의 고정 리비전 다운로드 경로로 확보하며 오프라인이면 실패한다. 이번 검증에서는 캐시 미존재 상태의 실다운로드를 다시 실행하지 않았다. 자체 수집 코퍼스를 “외부 호출 제한 시 제공 문서 묶음 대체” 예외라고 주장하지 않는다.

## 실제 선별·색인 결과

| 사례 | 후보 | 모델 선택/제외 | 강제 포함 자체 문서 | 최종 연결 문서 | 청크 |
|---|---:|---:|---:|---:|---:|
| 피카츄 진화 조건 | 30 | 3 / 27 | 88 | 90 | 96 |
| 이브이 진화 분기 | 30 | 4 / 26 | 103 | 104 | 122 |
| 미라이돈 바이올렛 설명 | 6 | 2 / 4 | 6 | 6 | 6 |

모델 선택 문서와 자체 문서는 겹치므로 단순 합산하지 않는다. 후보 중 모델이 제외한 자체 문서는 각각 1·8·4건이었고 모두 실제 색인에 포함됨을 검사했다. 자체 문서는 후보 30개 상한 밖에서도 전부 포함된다. 기본 문서 컬렉션의 누적 청크 수는 **224개**다. 전체 1,025종의 모든 설명 문서를 선색인한 결과가 아니라 세 대표 질문을 준비한 결과다.

각 사례에서 검색어 추출/후보 선별 JSON 응답을 실제로 확보했다(사례당 최초 2호출). 미라이돈의 요청 버전은 `violet`으로 해석됐다. 생성 한국어 도감 2건은 원문 ID·영어 원문·모델/검수/공식 여부를 포함한 원본 보완 레코드와 로컬 sidecar가 완전히 일치했다. 답변에서의 번역 표시와 버전 필터는 작업 5에서 별도 검증한다.

세 사례 각각의 오프라인 재실행에서 모델 호출 0회, 임베딩 호출 0회, 외부 원본 요청 0회, 카탈로그 검색 캐시 적중 1회였다. 재실행 직전/직후 컬렉션 청크 수는 각각 96→96, 218→218, 224→224로 유지됐다. 항목별 증분 색인 중의 누적 수이므로 처음 두 수가 최종 총량과 다르다.

검증 스크립트 실행 시 피카츄는 앞선 연결 점검 캐시를 재사용했다. 초기 청커 점검 후 조건 조각·0 플래그 안내를 보강해 청커 v2로 재구축했고, v1 컬렉션은 삭제하지 않고 비활성 상태로 보존했다. 재실행을 최초 호출이나 비용으로 중복 집계하지 않는다.

## 청킹과 식별자

- 기본 설정은 800자·100자 중복이다. 도감·특성의 짧은 문서는 한 청크로 보존하고 문서 간 경계를 합치지 않는다.
- 진화 체인은 JSON 간선/조건 행으로 먼저 나눈다. 행 내부 조건의 AND와 다른 행의 OR를 구별하고, ID·버전은 식별 필드이며 0인 요구 플래그는 요구가 없다는 안내를 붙인다.
- 긴 조건 행은 추가 분할하되 모든 조각에 출발/도착 종·체인 ID·조건 행·조각 번호·전체 조건 단정 금지·적용 범위를 반복한다. 원문 조건은 sidecar에 보존한다. 문서가 모든 게임별 예외를 보장하지 않는다는 범위를 유지한다.
- 청크 ID는 선택 item_id·원래 doc_id·청커 버전/설정·행/조각 번호의 해시다. 같은 원문이 여러 항목에 연결되어도 덮어쓰지 않는다. `item_id`와 `source_item_id`를 구별한다.
- 문서 컬렉션 서명에는 원본/코퍼스·스키마·청커 버전·청킹 설정·임베딩 모델/차원이 포함된다. 프로필 변경은 새 물리 컬렉션으로 분리하고 활성 포인터를 검증 후 전환한다.

이브이의 동일한 104개 연결 문서에 청크 크기를 **800→400자**로 바꿔 실제 재색인했을 때 **122→141청크**가 됐다. 중복 길이는 100자로 유지했다. 두 컬렉션 이름이 다르고 LLM·외부 원본 요청은 추가로 발생하지 않았다. 비교 후 기본 800자 컬렉션을 다시 활성화했다. 이 결과는 청크 수 변화이며 검색/답변 품질 향상을 뜻하지 않는다.

접두 제목·범위 안내는 임베딩용 텍스트에 추가되므로 최종 저장 문자열 전체가 800자 이하라는 뜻은 아니다. 800자는 분할 대상 본문 기준이다. 진화 조건 검증은 원문과의 구조 보존 검사이며 게임별 완전성 검증은 아니다.

## 캐시·진행과 실패 처리

검색어·선별 결과는 질문/선택 항목·후보 집합·프롬프트/모델·원본 서명에 따라 캐시한다. 검색 카탈로그 캐시와 임베딩 캐시는 별도다. 캐시 내용을 해시·구조·허용 ID로 검증하며, 오프라인에서 캐시 누락 시 네트워크로 대체하지 않는다. 출력 계약 위반은 최대 1회 수정 요청 후 실패한다. CLI는 예외 종류와 일반 안내만 출력하고 API 응답/키/프롬프트 전문/스택 추적은 출력하지 않는다.

색인 잠금으로 동시 쓰기를 막고 모든 임베딩 확보 후 upsert한다. 성공한 작업만 manifest·활성 포인터를 갱신한다. 동일 원문·프로필의 질문별 선택 문서는 누적되며 이전 질문의 정상 문서를 자동 삭제하지 않는다. 업데이트된 코퍼스는 다른 서명으로 분리한다.

온라인 검증 스크립트도 이미 있는 캐시는 재사용한다. 새 입력/설정이면 GMS 호출이 발생할 수 있다. 전체 GMS 가격·차감액 및 서비스 지연 목표 달성은 이번에 검증하지 않았다.

| 로컬 경로 | 내용 |
|---|---|
| `dataset/pokemon/ingestion/cache/` | 검색·LLM JSON·원문/번역 전체 provenance |
| `dataset/pokemon/ingestion/audit/` | 질문별 후보·선별/제외 사유·최종 문서·청크 연결 |
| `dataset/pokemon/ingestion/manifest_*.json` | 컬렉션별 항목·청크 ID 연결 |
| `dataset/pokemon/ingestion/active.json` | 다음 검색 단계에서 읽을 활성 문서 컬렉션 |
| `dataset/pokemon/vectorstore/` | 메타 및 문서 Chroma 저장소 |
| `outputs/pokemon/ingestion/verification.json` | 실제 사례·캐시·설정 비교 집계 |

위 데이터·응답·벡터·키 파일은 Git에 올리지 않는다. 원본 `items.json`, `documents.json`, `documents_ko_enriched.json`의 실행 전후 SHA-256 일치를 확인했다. 관련 테스트 37개와 `pip check`가 통과했다. 신규 8개 테스트는 항목 간 ID 충돌, 프로필 분리, 문자 유실, 조건 AND/OR, 번역 연결, 잘못된 버전/검색어, 후보 ID·사유 모순, LLM 캐시 변조·오프라인 무호출을 검증한다.

F2003~F2005의 이번 세 사례·설정 비교 범위를 실행 확인했다. 후보 검색의 재현성과 색인 무결성을 검증한 것이며 후보 선별의 정답률이나 전체 포켓몬 지원 품질을 측정한 것은 아니다. 다음 작업 5에서 두 컬렉션 근거 검색·중복 제거·LangGraph retrieve/generate·답변 인용을 연결한다.
