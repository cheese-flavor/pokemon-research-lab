# 포켓몬 백과형 RAG 서비스: 제출 점검

점검일: 2026-10-23. 서비스 가칭은 **포켓몬 리서치 랩**이다. 제품 성격은 **근거와 출처를 제공하는 포켓몬 백과형 RAG 서비스**, 구현 형태는 **Streamlit 웹 앱**이다. 공식 포켓몬 서비스가 아니며 외부 배포는 하지 않았다.

## 사용자에게 제공하는 가치

전국도감 1~1,025번 중 포켓몬을 선택해 도감·특성·진화 조건을 질문하고 실제 인용한 출처를 확인한다. 세대·타입·키·몸무게 등의 조건으로 탐색하고 결과에서 해당 포켓몬의 대화로 이동한다. 진화 조건 카드는 검색 근거의 조건 행을 표시한다. 대전 승리 추천이나 모든 게임·형태를 포괄하는 공략집은 범위에 포함하지 않는다.

## 이번 재실행

기존 로컬 캐시를 유지하고 순차 1회씩 실행했다. 최초 네트워크 호출 측정도, 통계적으로 안정적인 서비스 성능 시험도 아니다. 외부 호출 0회, 원본 세 파일 해시 유지. p95는 10개 측정값의 nearest-rank 방식으로 최대값과 같다. 준비 시간에는 캐시 자료 검증·읽기·색인 확인이 포함되고 캐시 생성 시간 0.000 표시는 소요가 전혀 없다는 뜻이 아니다.

캐시 p95 **2.426초**, 내부 초기 목표 30초 이내를 이 표본에서 충족했다. 원 요구사항의 수치 합격 기준으로 주장하지 않는다. 설계 Q01~Q10과 동일한 전수 실행은 아니며, 파이리 설명(Q03)·나옹 특성(Q05)의 별도 실제 답변 평가는 남아 있다. 기존 8개 RAG 구조 검증 사례와 조건 탐색 2개를 재사용했다.

포켓몬 자동 테스트 59개가 9.852초에 모두 통과했고, pip check도 의존성 문제 없음으로 통과했다. 구조/회귀 검사와 원문 사실 평가는 구별한다. 상세 단계 시간과 실행 결과는 로컬 outputs/pokemon/submission/verification.json에만 저장한다.

재현 명령(프로젝트 루트 PowerShell):

```powershell
streamlit_lab/.venv/Scripts/python.exe scripts/verify_pokemon_submission.py
streamlit_lab/.venv/Scripts/python.exe -m unittest discover -s tests -p "test_pokemon*.py" -q
streamlit_lab/.venv/Scripts/python.exe -m pip check
```

## 실행과 재현 순서

Python 3.11 이상에서 프로젝트 루트를 기준으로 실행한다. 기존 환경이 없으면 먼저 `python -m venv streamlit_lab/.venv`로 만든다.

```powershell
streamlit_lab/.venv/Scripts/python.exe -m pip install -r requirements-pokemon-rag.txt
streamlit_lab/.venv/Scripts/python.exe scripts/collect_pokemon_bulk.py
```

루트 .env.example의 빈 템플릿을 참고해 로컬 streamlit_lab/.env에 GMS_KEY를 직접 설정한다. 키 값을 화면·문서·Git에 옮기지 않는다. 다음 번역 단계부터 GMS 호출과 비용이 발생할 수 있다. 이미 보완 데이터가 있으면 재번역하지 않는다.

```powershell
streamlit_lab/.venv/Scripts/python.exe scripts/translate_pokemon_descriptions.py
streamlit_lab/.venv/Scripts/python.exe scripts/index_pokemon_metadata.py
streamlit_lab/.venv/Scripts/python.exe -m streamlit run streamlit_lab/app.py --server.address 127.0.0.1
```

번역의 용어 보정·검수 재현은 TRANSLATION.md·KOREAN_TERMS.md의 절차를 따른다. 위 명령만으로 기존 검수 이력과 동일함을 보장하지 않는다. 앱은 http://127.0.0.1:8501 에서 사용하며 첫 질문의 문서는 증분 준비된다. 종료는 실행 터미널 Ctrl+C다. 새 설치 환경 전체 재현은 이번 작업에서 실행하지 않았다. 검증 스크립트의 offline 실행은 해당 대표 질문의 준비/답변 캐시까지 있어야 하므로 새 설치에서 곧바로 통과하지 않는다. 온라인 대표 사례 준비는 RAG_VALIDATION.md·UI_VALIDATION.md를 따른다.

## 실행 화면과 평가 증거

작업 6의 실제 브라우저 기록은 UI_VALIDATION.md에 있다. 로컬 미리보기 outputs/pokemon/ui/evolution-preview.png는 Git 제외이며 이번 작업에서 새 화면을 촬영했다고 주장하지 않는다. 제출용 최종 화면 묶음은 아래를 직접 확인·촬영해 로컬 제출물에 첨부해야 한다. 프롬프트·키·데이터 전문은 포함하지 않는다.

- 대화: 포켓몬/버전, 답변 인용, 실제 사용 출처의 제목과 링크.
- 조건 탐색: 입력 조건, 해석 조건, 2종 결과, 선택 후 대화 이동.
- 진화 카드: 조건 행·AND/OR 안내·형태/범위·원문 링크.
- 예외: 결과 없음, 키/색인 누락 안내, 사용자용 안전한 오류.

그래프 구조와 청킹/Top-k 설정 비교 증거는 RAG_VALIDATION.md·INGESTION.md에 있다. 전체 답변/근거는 로컬에만 보관한다.

## 최종 체크리스트 적용 순서 (사용자 지정)

PDF 기준 요구사항을 먼저 마무리하고 루트의 `2회차_셀프·상호_체크리스트.xlsx`로 최종 점검한다. 원본의 체크리스트·작성 안내 시트를 읽었으며 27개 점검 항목을 확인했다. 현재 결과를 기입하거나 통과 처리하지 않았다.

최종 점검 때 원본은 보존하고 점검용 사본의 지정 입력 칸만 작성한다. 결과(G9:G35)는 통과·실패·미확인·해당없음, 증빙(H열)은 실제 캡처/파일명, 비고(I열)는 실패·미확인 사유를 기록한다. 확인 항목과 방법, 집계 수식은 유지한다. 미선택 심화와 포켓몬에 해당하지 않는 건강/금융 안내는 해당없음으로 구분한다. 실제 상호 점검의 점검자·피드백은 참여자가 작성해야 한다.

특히 20번의 최초/두 번째 질문 시간 비교와 26번의 스크린샷 첨부, 27번의 제출 문서·셀프/상호 체크리스트 포함을 최종 증빙으로 확인한다. 캐시 성능이나 자동 테스트만으로 이를 모두 통과 처리하지 않는다. 원본 엑셀은 이번 Git 변경에 포함하지 않는다.

후속 실측·Q03/Q05 원문 대조·발견 결함 수정·활성 402청크 상태는 [FINAL_REVIEW.md](FINAL_REVIEW.md)를 따른다. 최초 질문은 약 44초로 측정됐으며 최종 디자인 증빙·실제 상호 점검 등은 여전히 남아 있다.

## 원문에서 재확인한 제출 방식 (2026-10-23)

요구사항 PDF 21쪽은 최종 산출물을 Git README 또는 Word/PowerPoint 등으로 정리한 뒤 lab.ssafy.com에 업로드하도록 안내한다. 23쪽은 제출 파일명을 `AI 코어프로젝트 2_[주제명]_지역_반_성명.zip`으로 명시하며 산출물을 빠짐없이 제출하도록 한다. 21~23쪽의 포함 항목은 요구사항 정의서, RAG 설계문서, 실행 화면과 검증 결과/요구사항 대조표/테스트 결과표, 셀프·상호 체크리스트, Python 소스 및 수집·색인 스크립트, README다. 미선택 심화 결과는 수행했다고 쓰지 않는다.

Git 푸시만으로 ZIP 제출을 완료했다고 간주하지 않는다. 현재 제출용 ZIP은 만들지 않았다. 지역·반·성명과 실제 사람의 상호 점검이 남아 있다. 원본 요구사항 PDF·데이터·키는 Git에 넣지 않는다. 체크리스트 사본도 Git 제외를 유지하며, 제출용 체크리스트는 추후 승인된 로컬 패키지에 별도로 포함한다.

사용자가 GitLab 최신화를 다시 요청하여 이전 푸시 중단 지시를 해제했다. 강제 푸시나 과거 이력 재작성 없이 최신 코드·문서·화면 증빙 커밋을 반영한다.
