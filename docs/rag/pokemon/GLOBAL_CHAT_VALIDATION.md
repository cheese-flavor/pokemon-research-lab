# 전체 도감·대화 후속 검증

2026-10-23 KST. 사용자 추가 작업 6b 및 체크리스트 셀프 점검 기록이다. GitLab 푸시는 중단하며 GitHub 공개본만 갱신한다.

## 변경한 동작

- 왼쪽은 검색 입력과 이미지 아이콘을 가진 전국도감 1,025종 스크롤 목록이다. 전체 행을 한 번에 전달하되 44px 축소 이미지와 캐시를 사용하고, 표는 화면에 보이는 행을 렌더링한다. 기존 선택 상자·지식 준비 현황·12종 빠른 도감은 제거했다.
- 브랜드는 `Pokémon Research Lab`, 설명은 `포켓몬 정보 검색 · 도감 · 진화 조건`이다. 본문의 반복적인 홍보 문구도 기능 설명으로 바꿨다.
- 대화는 현재 도감 선택과 독립된 하나의 브라우저 세션 기록이다. 정확한 한국어·영문명과 `#25`, `도감 25`, `25번`을 연결하며, 긴 이름을 우선한다. 한 글자 이름인 뮤도 처리한다. 도감 목록 선택은 대화 주제를 바꾸지 않는다.
- 질문에 새로운 이름이 있으면 그 종으로 연결하고, 이름 없는 후속 질문은 이전 대화 대상과 직전 사용자 질문을 사용한다. 대상이 없거나 3종을 초과하면 구체화를 요청한다. 대화 기록 전체를 모델이나 원격 추적으로 전송하지 않는다.
- 최대 3종의 질문은 종별로 조회·답변하고 인용 번호를 전체 응답에서 다시 매긴다. 종 간 사실 비교를 별도 평가한 기능은 아니며, 종별 설명을 제공한다. 조건으로 찾는 질문은 기존 객관 조건 검사로 연결된다.
- 버전 필터·생성 번역 표시·원문 링크·인용된 출처만 표시하는 규칙은 유지한다. 기존 단일 항목 RAG의 다른 종 요청 차단도 유지하며 전체 대화 라우터가 그 앞에서 종을 결정한다.

## 준비 과정 재사용

이미 해당 종의 필수 자체 문서가 색인된 경우에 한해 준비용 프롬프트 1/2와 문서 임베딩을 반복하지 않는다. 코퍼스·청커·청크 설정·임베딩 모델·차원의 서명과 필수 문서/청크 ID를 대조한다. 실제 저장소에서 확인한 후 활성 포인터를 설정한다. 답변 검색과 생성은 그대로 수행하며 기존 질의 임베딩·답변 캐시도 유지한다.

버전 표현이 있거나 익숙하지 않은 질문·준비되지 않은 종·다른 색인 세대는 기존 준비 과정으로 돌아간다. `prepare_documents` CLI 기본값은 기존 두 프롬프트 경로여서 검색어·후보 선별 증빙을 다시 확인할 수 있다. 질의 문서 검색은 선택 종/출처 종과 버전을 계속 필터링한다.

같은 실행 환경에서 `파이리의 도감 설명을 알려줘`를 연속 측정했다. 파이리는 이미 필수 설명 문서가 준비된 상태였고, 이 정확한 질문의 답변/질의 벡터는 첫 측정에서 새로 생성됐다.

| 측정 | 전체 시간 | 준비 모델/문서 임베딩 | 질의 임베딩 | 답변 생성 |
|---|---:|---:|---:|---:|
| 준비된 종의 새 질문 | 7.390초 | 0 / 0회 | 1회 | 1회 |
| 같은 질문 반복 | 1.070초 | 0 / 0회 | 0회 | 0회 |

과거 신규 자료 준비를 포함한 두 질문은 약 44초였다. 질문·캐시 조건이 다르므로 동일 조건의 44→7초 개선 실험으로 해석하지 않는다. 처음 다루는 종은 여전히 준비 비용이 발생한다. 브라우저에서 2종의 새 질문은 19.03초로 측정됐다. 모든 종/질문의 지연 목표를 달성했다는 주장은 하지 않는다.

## 실행한 점검

- 포켓몬 회귀 테스트 70개 통과. 전역 이름·번호 라우팅, 새 대상 우선, 후속 질문, 인용 묶음 재번호, 잘못된 번호의 이전 종 대체 금지, 준비 자료 재사용 및 버전/설정 변경 시 우회 금지를 포함한다.
- 메타 색인 오프라인 재실행 두 번 모두 1,025→1,025건, 추가 임베딩 0회. 25번의 저장 텍스트가 준비 레코드와 일치하고 6능력치와 합계를 포함함을 확인했다.
- 기존 RAG 8사례, Top-k 3/5/8 비교와 오프라인 답변/출처 동일성 확인. 별도 제출 10사례 캐시 재현과 입력 해시 유지 확인. `pip check` 통과.
- 실제 브라우저에서 피카츄 도감을 유지한 채 파이리 질문, 2종 대화, 메타/문서 출처 구분, 2종 조건 결과와 빈 결과, 진화 조건, 미지원 질문을 확인했다.
- 키/색인 누락과 안전 오류는 별도 8502 포트의 결함 주입 점검 화면에서 확인했다. 실제 `.env`나 색인을 삭제하지 않았다. 오류 원문과 추적 정보·테스트 비밀 문자열이 화면에 나타나지 않았다.
- 기능별 실제 캡처 목록은 루트 `result/README.md`에 있다. 캡처는 데이터 전문이나 키 파일이 아니다.

## 체크리스트 판정

원본을 보존한 사본의 지정 입력만 채웠다. 확인 항목·방법·집계 수식·스타일·병합·선택 목록·고정 창은 보존했고, 통과 17 / 실패 2 / 미확인 2 / 해당없음 6 / 미기입 0으로 집계됐다. 상호 피드백 입력란은 비워두었다. 실제 사람의 점검자로 에이전트를 기재하지 않고 자동 셀프 점검임을 표시했다.

- 10번 실패: 기존 항목별 대화 분리 기준과 사용자가 새로 요청한 전체 대화 유지 정책이 다르다. 다른 종의 출처가 섞이는 버그와 구분한다.
- 20번 미확인: 준비된 종의 두 번 측정은 했으나 신규 종 전체와 운영 지연 적합성의 최종 판단은 유보했다.
- 25번 실패: 위 정책 차이와 F2004의 질문 시점 원격 검색 해석이 남았다.
- 27번 미확인: 실제 사람의 상호 점검과 최종 제출 패키지는 완료되지 않았다.

워크북은 로컬 `outputs/pokemon/checklist-review/`에만 있으며 공개 Git에 포함하지 않는다. 최종 제출 승인 완료로 표시하지 않는다.
