# 작업 1: 포켓몬 데이터 준비

## 범위와 재현

전국도감 **1~1,025번 전체 종**과 각 종의 기본 개체를 수집한다. 정규 수집기는 공식 PokéAPI 저장소의 CSV 20개를 특정 커밋으로 고정해 받는다. Python 표준 라이브러리만 사용하며 GMS/API 키가 필요 없다. 저장 위치는 Git에서 제외한 `dataset/pokemon/`이다.

```powershell
python scripts/collect_pokemon_bulk.py
python scripts/collect_pokemon_bulk.py --offline
python -m unittest discover -s tests -p test_pokemon_collection.py -v
```

`--offline`은 저장된 원본 캐시만으로 결과를 재생성한다. 캐시가 하나라도 없으면 실패하며 네트워크로 대체하지 않는다. 기본 실행도 이미 받은 파일은 다시 호출하지 않는다. SHA-256으로 캐시 변조·손상을 검사한다. 원본 커밋은 `2bf639e5572812a67d2b94903fdcb9d095f5aeb2`다.

`collect_pokemon.py`는 초기 1~151번 API 파일럿 유틸리티이며 정규 수집 경로가 아니다. 추가 실행 결과는 `dataset/pokemon_pilot/`에 분리하여 정규 결과를 덮어쓰지 않는다. 전체 범위 확정 후 초기 API 수집 프로세스는 중단했다. 기존 API 캐시는 로컬에만 남는다.

## 저장 파일

| 로컬 파일 | 내용 |
|---|---|
| `items.json` | 종 ID, 기본 개체 ID, 한국어·영문명, 타입, 최초 등장 세대, 키·몸무게, 전설/환상 여부, 특성, 능력치, 항목당 색인 텍스트, 출처와 수집 시각 |
| `documents.json` | 항목과 연결된 한국어/영어 도감 설명, 버전 그룹별 특성 설명, 진화 체인 분기 조건 |
| `manifest.json` | 고유 항목 수, 문서 종류·언어별 건수, 한국어 결측, 요청·캐시 횟수와 한계 |
| `raw/bulk_커밋/*.csv` | 고정 커밋의 원본 CSV 20개 |
| `raw/bulk_커밋/sources.json` | 원본 URL·실제 최초 수집 UTC 시각·파일별 SHA-256 |

항목 ID는 `pokemon-species:번호`다. 기본 개체는 `varieties.is_default`로 선택하여 종 ID와 형태별 개체 ID를 혼동하지 않는다. 문서 ID는 항목·문서 종류·URL·언어·버전·특성 ID로 생성하므로 동일 설명도 버전이 다르면 독립적으로 유지한다. 진화 체인은 관련 체인 전체이며 현재 항목 이외의 종이 들어갈 수 있다.

타입·종·특성의 한국어명은 CSV의 언어 ID를 `languages.csv`와 대조하여 가져온다. 없는 이름은 결측으로 보존하거나 표시용 영문명을 사용하며 임의 번역하지 않는다. 줄바꿈·페이지 구분 제어문자 등은 공백으로 정규화한다. 번역·요약·LLM 생성은 하지 않았다. 진화 조건은 원본 CSV 필드와 버전 그룹을 유지하고 트리거·아이템의 식별명을 연결했다. 모든 ID 참조를 한국어로 번역한 상태는 아니다.

## 출처와 이용 조건 (2026-10-22 확인)

- API 문서 및 Fair Use: https://pokeapi.co/docs/v2
- 종: `https://pokeapi.co/api/v2/pokemon-species/{id}/`
- 기본 개체: 종의 `varieties`에 연결된 `pokemon` URL.
- 타입·특성·진화: API 원문의 `type`, `ability`, `evolution_chain` URL.
- PokéAPI 프로젝트 라이선스: https://github.com/PokeAPI/pokeapi/blob/master/LICENSE.md
- 실제 일괄 수집 출처: https://github.com/PokeAPI/pokeapi/tree/2bf639e5572812a67d2b94903fdcb9d095f5aeb2/data/v2/csv
- 문서의 원문 URL은 실제 다운로드한 CSV를 가리킨다. 항목 ID·언어·버전으로 해당 행을 식별한다. 복수 원본 결합 문서에는 관련 원본 URL도 저장한다.

PokéAPI는 인증 없이 읽기 전용 GET으로 접근할 수 있는 교육용 공개 API다. Fair Use는 응답의 로컬 캐시와 서버 부하 절제를 요구한다. 초기 API 수집기는 순차 요청·0.25초 간격·일시 오류 재시도·숫자형 Retry-After를 적용했다. 정규 bulk 수집기는 GitHub 원본 파일에 순차 요청·0.25초 간격·최대 4회 시도와 지수 대기·로컬 캐시·해시 검증을 적용한다. 고정 커밋 캐시를 자동 갱신하지 않는다.

프로젝트 코드의 재배포 조건과 포켓몬의 문구·캐릭터·이미지·상표 권리는 별개다. API 공개를 원작 콘텐츠의 CC0 허락으로 취급하지 않는다. 최초 텍스트 수집 단계에는 이미지나 스프라이트를 포함하지 않았다. 2026-10-23 사용자 요청 후 화면용 이미지 1,025종을 별도 로컬 캐시에 수집했으며, 원본 파일은 Git에 포함하지 않는다. 현재 표시·출처·이용 범위는 [ARTWORK.md](ARTWORK.md)를 따른다. 수집 데이터와 캐시는 GitLab에 올리지 않고 재현 스크립트·출처·집계 검증 결과만 올린다. 공식 포켓몬 서비스라고 표시하지 않는다.

## RAG 적용 전 확인할 한계

1. 1~151번을 수집해도 타입·특성·능력치가 1세대 당시 기준이라는 뜻은 아니다. 현재 API 기본 형태 스냅샷이다.
2. 도감 설명의 `version`과 특성 설명의 `version_group`은 서로 다른 단위다. 최종 검색 필터 설계에서 구별해야 한다.
3. 진화 조건은 API의 구조화된 원문 필드를 보존했다. 모든 게임별 예외를 완전하게 제공하는 것으로 간주하지 않는다. 특정 버전 근거가 없으면 확인되지 않는다고 답해야 한다.
4. 한국어와 영어 설명만 수집한다. 같은 내용도 버전이 다르면 보존한다. 검색 단계의 중복 제거는 원본 데이터 삭제와 구분한다.
5. 기술 습득·출현 위치·게임별 상세 변경 이력은 이번 수집 범위에 없다. 해당 질문을 지원하려면 후속 설계에서 범위 확장과 출처를 결정해야 한다.
6. 메타데이터와 설명문이 확보되어도 LLM 검색어 추출·후보 선별·청킹·임베딩·LangGraph·답변 인용은 별도 작업이다. 이번 수집기로 F2002~F2012 완료를 주장하지 않는다.

- 이브이 진화 체인의 여러 분기 조건은 어떻게 다른가? 단, 이 체인을 특정 게임의 전체 가능 목록으로 간주하지 않는다.
