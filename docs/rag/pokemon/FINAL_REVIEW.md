## 외부 문서 수집 F2004

12~13쪽은 외부 출처 후보 검색, 프롬프트 2 선별, 자기 항목 문서 강제 포함, 본문/출처 확보와 검색어 캐시를 요구한다. 13쪽의 문서 묶음 대체는 외부 호출이 제한되는 환경에 대한 조건부 허용이다. 현재 환경이 그 제한에 해당한다고 주장하지 않는다.

현재 구현은 다운로드한 고정 외부 PokéAPI CSV에서 파생한 출처 연결 카탈로그를 검색한다. 매 질문마다 원격 검색 서비스를 호출하지 않는다. 실제 다운로드·해시 검증과 검색/선별은 구현됐지만, 질문 시점의 원격 검색을 요구하는 해석에는 차이가 있으므로 SUBMISSION.md의 부분 확인 판정을 유지한다. 새 출처 결합이나 심화 기능을 추가한 것으로 세지 않는다.

새 두 질문의 후보 30개에 대한 선택/제외 이유, 원문 연결과 자기 문서 강제 포함을 실제 audit에서 확인했다. 파이리 선택 6/제외 24, 필수 76문서·77청크; 나옹 선택 4/제외 26, 필수 99문서·101청크. 모델이 제외한 자기 문서 후보 각각 5개도 코드에서 복원됐다. 반복 실행 원격 자료 요청 0, 검색 캐시 적중, 추가 모델/임베딩 호출 0을 확인했다. 활성 설명 컬렉션은 기존 224에서 **402청크**로 증가했으며 원본 데이터 세 파일 해시는 유지됐다.

전체는 호출 경계의 perf_counter이며 구성 요소와 초기화/검증/파일 저장 등이 달라 단순 합과 같지 않다. 준비 단계 중 검색어 추출 약 5.889/4.173초, 후보 선별 약 23.400/26.005초, 문서 임베딩/저장 약 5.105/4.126초다. 콜백 경계로 잰 구간이며 HTTP 호출 시간만 분리한 값은 아니다.

발견한 결함: 답변이 검색 결과 일부에 없는 내용을 전체 수집 문서에도 없는 것처럼 표현했다. 프롬프트 3을 현재 검색된 근거의 범위로 제한하도록 수정했다. 다시 실제 GMS 생성한 나옹 답변은 미확인 범위를 현재 검색된 근거로 한정하고 status=insufficient로 부분 답변임을 표시했다. 검증 스크립트도 부분 근거 답변에 answered를 강제하지 않도록 수정했다. 이후 두 사례 오프라인 재실행에서 답변/출처 동일·추가 호출 0, 기존 8사례 RAG 검증도 통과했다.

화면 결함: 요청 실패의 상세 안내가 접힌 진행 상자 안에 숨었다. 안내와 확인 번호를 진행 상자 밖에 표시하도록 고쳤다. 키·프롬프트·예외 원문은 표시하지 않는다.
